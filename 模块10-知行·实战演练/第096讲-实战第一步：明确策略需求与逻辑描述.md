# 第096讲 实战第一步：明确策略需求与逻辑描述

> 所属模块：模块10｜知行·实战演练  
> 建议时长：10–12 分钟  
> 内容状态：已完成（课程版 v1.0）

> 风险提示：本文仅用于量化投资知识教育，不构成任何投资建议。实盘交易部署会产生真实损失，必须经过授权、测试和独立风控。

## 本讲目标

- 把策略需求写成可测试规范。
- 区分经济假设、信号、组合与约束。
- 建立上线验收与失败标准。

## 先写需求，不先写代码

策略项目应从“解决什么问题”开始：追求绝对收益、降低回撤、提供对冲还是跟踪基准。目标不同，数据与评价也不同。

## 一页策略说明书

1. **目标与基准**：要超过谁，风险预算多少。
2. **交易范围**：市场、资产、流动性和排除条件。
3. **假设**：优势为何存在，谁在另一侧。
4. **信号**：输入、公式、频率和时点。
5. **组合**：权重、持仓数、再平衡和约束。
6. **执行**：订单时间、类型、显性交易费用和成交模型。
7. **风控**：单票、组合、回撤与异常。
8. **验收**：样本外、成本、稳健性和容量标准。

## 模糊词清理

把“趋势明显”“估值合理”“风险较低”改成字段、窗口、阈值和比较对象。仍需人工判断的部分也要记录输入与权限。

## 失败定义

在实验前写出什么结果会否定假设、什么偏离会暂停实盘交易。没有失败标准，研究会不断加条件直到曲线变好。

## 最小可行策略

先实现最简单基线，跑通数据—信号—订单—账本—报告，再增加复杂度。工程闭环比首版收益高更重要。

## 实战交付：让别人能够独立复现

围绕“实战第一步：明确策略需求与逻辑描述”形成可交付的研究闭环。完工标准不是代码在作者电脑上运行过一次，而是另一位读者能按说明重建环境、运行测试并解释输出。

1. 冻结需求、输入字段、参数、信号时点、成本口径和输出结构。
2. 把数据校验、策略逻辑、账本、指标、日志和异常处理拆成可测试模块。
3. 使用同一份输入分别运行 Python 与 R，实现逐日结果与指标对账。
4. 保留 README、运行命令、测试记录、已知限制和上线前检查清单。

## 常见误区与修正

- 只交付代码片段而没有输入、环境和运行说明；这不构成可复现产物。
- Python 与 R 使用不同默认参数或缺失值规则；跨语言对账必须逐列进行。
- 把回测通过等同于可实盘；模拟交易、权限隔离、监控和故障恢复仍需独立验收。

## 实战验收清单

- [ ] 从干净环境可按 README 一次运行成功
- [ ] 输入校验和关键逻辑有自动测试
- [ ] Python 与 R 输出在约定容差内一致
- [ ] 日志、监控、异常恢复和风险限制均有文档

## 本讲小结

- 策略需求应覆盖目标、数据、信号、组合、执行、风控与验收。
- 模糊词必须转成可观察条件。
- 先定义失败，再开始实验。
