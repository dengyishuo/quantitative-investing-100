# 第098讲 在聚宽/米筐上完成一次完整回测并看懂报告

> 所属模块：模块10｜知行·实战演练  
> 建议时长：10–12 分钟  
> 内容状态：已完成（课程版 v1.0）

> 风险提示：本文仅用于量化投资知识教育，不构成任何投资建议。实盘交易部署会产生真实损失，必须经过授权、测试和独立风控。

## 本讲目标

- 完成一次平台回测并核对关键设置。
- 读懂收益、回撤、交易和风险报告。
- 用订单明细而非曲线判断可信度。

## 上传代码前先锁定口径

记录平台、数据版本、回测区间、基准、初始资金、频率、复权、显性交易费用、滑点和成交规则。平台默认值不是策略定义。

## 运行步骤

1. 先用短区间调试，打印均线、信号、订单和持仓。
2. 手工核对几天，确认没有同价前视。
3. 扩展全样本，保存代码与参数。
4. 运行样本外和成本压力版本。
5. 导出交易明细与每日净值。

## 看懂报告

先看净值和回撤路径，再看年化收益率、年化波动率、夏普比率、换手率和交易成本。比较基准与空仓现金。检查收益是否集中于少数年份或交易。

## 订单审计

抽取首次买入、反转、跳空和最后持仓，核对信号时间、提交时间、成交价、数量与显性交易费用。很多回测错误只在订单层可见。

## 跨平台差异

聚宽、米筐或本地框架可能采用不同复权、日历和撮合。不要要求最终小数完全相同，先逐日对齐输入、信号和订单，定位口径差异。

## 产出

保存策略说明书、代码版本、参数、环境、净值、交易表、指标与已知限制，形成可复现包。

## 实战交付：让别人能够独立复现

围绕“在聚宽/米筐上完成一次完整回测并看懂报告”形成可交付的研究闭环。完工标准不是代码在作者电脑上运行过一次，而是另一位读者能按说明重建环境、运行测试并解释输出。

1. 冻结需求、输入字段、参数、信号时点、成本口径和输出结构。
2. 把数据校验、策略逻辑、账本、指标、日志和异常处理拆成可测试模块。
3. 使用同一份输入分别运行 Python 与 R，实现逐日结果与指标对账。
4. 保留 README、运行命令、测试记录、已知限制和上线前检查清单。

## 常见误区与修正

- 只交付代码片段而没有输入、环境和运行说明；这不构成可复现产物。
- Python 与 R 使用不同默认参数或缺失值规则；跨语言对账必须逐列进行。
- 把回测通过等同于可实盘；模拟交易、权限隔离、监控和故障恢复仍需独立验收。

## 实战验收清单

- [ ] 从干净环境可按 README 一次运行成功
- [ ] 输入校验和关键逻辑有自动测试
- [ ] Python 与 R 输出在约定容差内一致
- [ ] 日志、监控、异常恢复和风险限制均有文档

## 本讲小结

- 平台默认参数必须显式记录。
- 先审计订单，再相信绩效曲线。
- 回测产出应包含完整可复现材料。
