# 第102讲 策略上线前最后的检查清单，避免灾难性错误

> 所属模块：模块10｜知行·实战演练  
> 建议时长：10–12 分钟  
> 内容状态：已完成（课程版 v1.0）

> 风险提示：本文仅用于量化投资知识教育，不构成任何投资建议。实盘交易部署会产生真实损失，必须经过授权、测试和独立风控。

## 本讲目标

- 完成数据、模型、工程、风险和运营五类检查。
- 明确上线批准与回滚条件。
- 形成可签署的发布清单。

## 上线是风险事件

策略从研究进入真实账户后，错误会变成现金流。上线清单的作用是阻止“大家都以为别人检查过”。

## 数据

来源、许可、时区、复权、公告时间、缺失与备用源已确认；历史与实时字段一致；断流和异常能告警。

## 模型

代码锁定、无前视、样本外与稳健性通过；参数来源清楚；特征和预测有漂移阈值；已知失效环境记录。

## 执行

订单类型、最小单位、涨跌停、停牌、部分成交、重复回报、重启恢复和撤单已测试；交易成本与容量压力后仍可接受。

## 风险

单资产、行业、因子、杠杆、流动性、回撤和压力损失限额已配置；限额在独立层执行；紧急停机与减仓可用。

## 运营

权限最小化、密钥安全、时钟同步、监控值班、券商对账、版本发布和事故手册完备。

## 发布与回滚

采用小资金、少品种、分阶段放量；记录批准人、版本和生效时间。回滚到上一版本与清仓不是同一动作，都需预案。

## 最后问题

如果负责人今天无法上线，你能否仅凭文档安全运行和停止系统？若不能，项目还未准备好。

## 实战交付：让别人能够独立复现

围绕“策略上线前最后的检查清单，避免灾难性错误”形成可交付的研究闭环。完工标准不是代码在作者电脑上运行过一次，而是另一位读者能按说明重建环境、运行测试并解释输出。

1. 冻结需求、输入字段、参数、信号时点、成本口径和输出结构。
2. 把数据校验、策略逻辑、账本、指标、日志和异常处理拆成可测试模块。
3. 使用同一份输入分别运行 Python 与 R，实现逐日结果与指标对账。
4. 保留 README、运行命令、测试记录、已知限制和上线前检查清单。

## 常见误区与修正

- 只交付代码片段而没有输入、环境和运行说明；这不构成可复现产物。
- Python 与 R 使用不同默认参数或缺失值规则；跨语言对账必须逐列进行。
- 把回测通过等同于可实盘；模拟交易、权限隔离、监控和故障恢复仍需独立验收。

## 实战验收清单

- [ ] 从干净环境可按 README 一次运行成功
- [ ] 输入校验和关键逻辑有自动测试
- [ ] Python 与 R 输出在约定容差内一致
- [ ] 日志、监控、异常恢复和风险限制均有文档

## 本讲小结

- 上线清单覆盖数据、模型、执行、风险和运营。
- 发布应分阶段，并具有明确回滚与停机方案。
- 职责、版本和批准必须可审计。
