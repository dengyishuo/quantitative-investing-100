# 第028讲 动手搭建你自己的轻量级量化数据库

> 风险提示：本文仅用于量化投资知识教育，不构成任何投资建议。数据示例与方法需结合真实市场规则验证。

## 本讲目标

- 设计原始、标准化和特征三层数据库。
- 掌握主键、版本与增量更新思路。
- 建立可复现的数据访问接口。

## 目标：轻量但不随意

个人数据库不需要一开始追求分布式架构，但必须保证来源明确、更新可重复、历史不被静默覆盖。

## 三层结构

- **Raw 原始层**：保存供应商原始响应，只追加、不修改。
- **Clean 标准层**：统一代码、时区、频率、单位和复权字段。
- **Feature 特征层**：保存研究使用的收益、因子和标签，并记录计算版本。

## 核心表

证券主表记录代码、市场、上市退市日期和资产类型；交易日历表记录各市场开闭市；行情表以证券和时间为主键；公司行动表保存事件和生效日；基本面表同时保留报告期、公告时间和版本。

## 更新流程

每次任务先读取最新成功时间，拉取增量数据，进行校验，再原子写入。失败时不更新水位。对回溯修订的数据保留版本或快照，确保过去研究可重现。

## 存储选择

小规模日频可使用 Parquet 配合分析引擎，关系与元数据可用 SQLite 或 PostgreSQL。选择标准是数据量、并发、查询方式和维护能力，而不是技术潮流。

## 最低工程规范

配置与密钥分离、UTC 与本地时区清楚、日志可追踪、质量测试自动化、备份可恢复，并提供统一读取函数，避免每个策略各写一套口径。

## 验收

给定数据版本、截止时间和查询参数，任何一次研究都应能重新得到相同输入。可复现性比界面漂亮更重要。

## 先从一个可复现查询开始设计

数据库的验收目标可以写成一句话：给定“数据版本、知识截止时间、资产范围和字段”，任何研究者都能得到相同输入。这个目标反推表结构必须同时保存业务时间和系统时间，而不只是最终数值。

例如基本面记录至少包含报告期、公告时间、供应商采集时间和版本；查询“某日当时可见数据”时，既要排除未来公告，也要选择当时最新版本。若表里只留最终修订值，数据库再快也无法支持可信回测。

## 三层结构如何阻止错误扩散

Raw 层保存供应商原文或原始文件并生成校验值，任何修正都不覆盖它；Clean 层统一代码、时间、单位和状态，并保留清洗规则版本；Feature 层只保存明确公式产生的研究字段，记录输入版本和参数。

当某个因子异常时，可以从 Feature 追到 Clean，再追到 Raw，判断是公式、清洗还是供应商源数据问题。如果只有一张被反复修改的大表，错误来源和受影响研究都很难定位。

## 一次安全的增量更新

更新任务可按以下顺序运行：下载到临时区域；验证文件、日期和记录数；写入 Raw；生成 Clean；执行唯一性、完整性和业务逻辑检查；生成 Feature；全部通过后再更新“最新成功水位”。任一步失败都不应让半成品成为正式版本。

回补历史时要标明受影响区间，并触发依赖特征的重算。若数据修订了但特征层没有重算，数据库内部会出现来源不一致的混合版本。

## 一组够用的核心字段

| 对象 | 关键字段 |
|---|---|
| 证券主表 | 永久标识、市场代码、资产类型、上市与退市区间 |
| 交易日历 | 市场、交易日、开闭市与特殊时段 |
| 行情表 | 永久标识、事件时间、OHLCV、交易状态、来源版本 |
| 公司行动 | 事件类型、公告时间、生效时间、现金与股数变化 |
| 基本面 | 报告期、公告时间、采集时间、版本、字段口径 |
| 数据血缘 | 输出表、输入版本、处理代码版本、运行时间 |

永久标识与展示代码应分开，因为证券代码可能变化或被重复使用。时间字段也应写明时区，不能依赖数据库或操作系统默认值。

## 轻量不等于没有运维

至少需要自动质量报告、更新日志、失败告警、备份和恢复演练。备份文件存在不代表可以恢复，应定期在隔离位置重建一小段数据并运行查询。密钥不得写进代码或提交到仓库，数据授权范围也应进入元数据。

个人项目不需要过早引入复杂分布式组件。能稳定重放、定位错误和恢复数据，比采用流行架构更重要。

## 数据审计：先证明当时真的看得到

围绕“动手搭建你自己的轻量级量化数据库”建立一张数据审计卡。目标不是把表填满，而是证明每个字段在决策时点真实可得、口径一致并可追溯。

1. 记录字段定义、来源、原始频率、发布时间、修订规则与授权范围。
2. 区分事件发生时间、数据发布时间、采集时间和策略可用时间。
3. 统计缺失、重复、异常和覆盖率，并保留原始值与清洗日志。
4. 用小样本从原始数据重建一个指标，核对复权、单位和时间对齐。

## 参考资料

- [pandas 官方用户指南](https://pandas.pydata.org/docs/user_guide/index.html)：时间序列、缺失值与数据变换。
- [scikit-learn：Common pitfalls](https://scikit-learn.org/stable/common_pitfalls.html)：数据泄漏与训练、测试隔离。
- **适用条件与边界**：数据许可、交易日历、公司行动和披露时点因市场而异；今天修订后的数据库不等于历史当时可见信息。
- **主要失败模式**：使用后见修订数据、幸存股票池或错误复权，并把缺失值静默填充成不存在的事实。

## 常见误区与修正

- 用今天看到的历史数据假装当时已经可得；应使用 point-in-time 快照或发布时间约束。
- 直接删除缺失值而不解释缺失机制；缺失本身可能包含选择偏差。
- 只保存清洗后结果；没有原始快照和日志就无法复现与审计。

## 实战验收清单

- [ ] 每个核心字段有来源和更新时间
- [ ] 不存在使用未来修订值的前视偏差
- [ ] 缺失、异常、重复与退市样本均有处理记录
- [ ] 从原始数据到研究表的变换可以重放

## 本讲小结

- 轻量数据库也应分离原始、标准和特征层。
- 时间、主键和版本决定研究能否复现。
- 增量更新必须先校验再提交，并保留失败日志。
