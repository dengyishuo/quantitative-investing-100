# 第099讲 从回测到模拟交易：让策略跑起来，感受真实冲击

> 风险提示：本文仅用于量化投资知识教育，不构成任何投资建议。实盘交易部署会产生真实损失，必须经过授权、测试和独立风控。

## 本讲目标

- 理解模拟交易验证的对象与局限。
- 搭建实时数据、信号、订单和对账链路。
- 设定从模拟交易到小资金实盘交易的门槛。

## 模拟交易验证什么

模拟交易不能证明盈利，却能发现历史回测看不到的运营问题：数据延迟、时区、调度、订单状态、停牌、显性交易费用、重启和通知。

## 最小链路

> 实时数据 → 特征 → 信号 → 风险检查 → 模拟订单 → 成交回报 → 持仓账本 → 监控告警

每一步记录时间戳与唯一事件 ID，程序重启后能够恢复未完成订单和仓位。

## 与回测对账

每日生成“理论目标—模拟订单—实际模拟持仓”差异。解释信号、价格、显性交易费用和成交偏离，而不是只比较最终净值。

## 真实感设置

使用下一可交易时点、合理滑点、部分成交与订单拒绝；模拟停牌、接口断线和重复推送。过于理想的模拟交易只是另一层回测。

## 晋级门槛

连续运行覆盖足够信号与异常；无未解释账差；告警、恢复和人工接管通过演练；扣除模拟交易成本后的表现仍在预期范围。进入小资金实盘交易后仍应限制品种和风险。

## 模拟交易验证的是系统行为

回测读取一段完整历史，模拟交易则必须等待数据实时到达，并处理迟到、重复、修订和断流。它能检验调度、接口、订单状态、账本和告警是否共同工作，却仍不能完整复制真实排队位置、市场冲击和资金压力。

因此模拟交易的首要评价不是赚了多少，而是每个事件是否按预期发生、偏差能否解释、故障能否恢复。

## 每个事件都要可重放且幂等

行情、信号、风控、订单和成交回报应有唯一事件 ID、发生时间和接收时间。程序收到重复消息时不得重复下单；重启后能够从最后确认状态恢复，并重放未处理事件而不改变已完成结果。

可以在测试环境主动重复发送同一成交回报或让程序在下单后立刻崩溃，验证账户不会出现双倍持仓。

## 三本账必须每日对齐

理论账记录模型目标，模拟执行账记录订单与成交，券商或平台账记录外部认可的现金和持仓。每日比较三者，差异按信号延迟、风控拦截、未成交、费用、公司行动或数据错误分类。

无法解释的差异不能滚入下一日继续积累。对账失败时应限制新增风险，并保留原始回报供复盘。

## 故障演练比正常运行更重要

至少注入行情延迟与中断、重复推送、订单拒绝、部分成交、撤单失败、时钟偏差、程序重启、数据库不可用和告警通道失效。每个场景都要有预期系统状态、自动动作、人工负责人和恢复验证。

演练目标不是系统永不出错，而是错误不会静默扩大，且能够在明确时间内恢复到可核对状态。

## 回测与模拟交易怎样逐层对账

同一日期比较输入数据、特征、信号、目标仓位、风控后仓位、订单、成交与费用。若输入相同而信号不同，是计算或版本问题；信号相同而持仓不同，多半来自风险或执行；持仓相同而净值不同，则检查价格、费用和公司行动。

逐层对账比比较两条净值曲线更快定位根因。

## 从模拟盘晋级的评分卡

评分卡至少覆盖运行稳定性、数据及时性、账本一致性、订单成功率、成交偏差、告警响应、故障恢复、成本后表现和压力限额。还要达到足够事件数量，而不只是运行了足够日历天数。

进入小资金阶段仍应限制资产、订单和最大损失，并保持模拟或影子组合并行。实盘暴露只能随证据逐步增加。

## 实战交付：让别人能够独立复现

围绕“从回测到模拟交易：让策略跑起来，感受真实冲击”形成可交付的研究闭环。完工标准不是代码在作者电脑上运行过一次，而是另一位读者能按说明重建环境、运行测试并解释输出。

1. 冻结需求、输入字段、参数、信号时点、成本口径和输出结构。
2. 把数据校验、策略逻辑、账本、指标、日志和异常处理拆成可测试模块。
3. 使用同一份输入分别运行 Python 与 R，实现逐日结果与指标对账。
4. 保留 README、运行命令、测试记录、已知限制和上线前检查清单。

## 参考资料

- [Backtrader 官方文档](https://www.backtrader.com/docu/)：事件驱动回测框架的行为定义。
- [Python logging 官方文档](https://docs.python.org/3/library/logging.html)：结构化日志与严重级别的实现依据。
- **适用条件与边界**：平台回测结果取决于撮合、费率和数据实现；模拟交易仍不能完整复现实盘排队、冲击和故障。
- **主要失败模式**：研究与生产代码分叉、日志不可追溯、上线无回滚、告警无责任人、收益无法归因。

## 常见误区与修正

- 只交付代码片段而没有输入、环境和运行说明；这不构成可复现产物。
- Python 与 R 使用不同默认参数或缺失值规则；跨语言对账必须逐列进行。
- 把回测通过等同于可实盘；模拟交易、权限隔离、监控和故障恢复仍需独立验收。

## 本讲小结

- 模拟交易主要验证实时工程和执行一致性。
- 理论、订单与持仓必须每日对账。
- 从模拟交易到实盘交易应依据明确的运营与风险门槛。
