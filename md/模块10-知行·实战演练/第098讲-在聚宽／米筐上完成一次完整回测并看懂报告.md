# 第098讲 在聚宽/米筐上完成一次完整回测并看懂报告

> 风险提示：本文仅用于量化投资知识教育，不构成任何投资建议。实盘交易部署会产生真实损失，必须经过授权、测试和独立风控。

## 本讲目标

- 完成一次平台回测并核对关键设置。
- 读懂收益、回撤、交易和风险报告。
- 用订单明细而非曲线判断可信度。

## 上传代码前先锁定口径

记录平台、数据版本、回测区间、基准、初始资金、频率、复权、显性交易费用、滑点和成交规则。平台默认值不是策略定义。

## 运行步骤

1. 先用短区间调试，打印均线、信号、订单和持仓。
2. 手工核对几天，确认没有同价前视。
3. 扩展全样本，保存代码与参数。
4. 运行样本外和成本压力版本。
5. 导出交易明细与每日净值。

## 看懂报告

先看净值和回撤路径，再看年化收益率、年化波动率、夏普比率、换手率和交易成本。比较基准与空仓现金。检查收益是否集中于少数年份或交易。

## 订单审计

抽取首次买入、反转、跳空和最后持仓，核对信号时间、提交时间、成交价、数量与显性交易费用。很多回测错误只在订单层可见。

## 跨平台差异

聚宽、米筐或本地框架可能采用不同复权、日历和撮合。不要要求最终小数完全相同，先逐日对齐输入、信号和订单，定位口径差异。

## 产出

保存策略说明书、代码版本、参数、环境、净值、交易表、指标与已知限制，形成可复现包。

## 建立回测运行清单

运行前把设置分成四组：数据口径包括证券池、复权、公司行动和时区；交易口径包括信号时间、订单类型、成交价与未成交处理；费用口径包括佣金、税费、滑点和融资成本；评价口径包括基准、无风险收益、年化周期和统计区间。

将平台页面上的设置截图或导出配置，并与代码内参数一起保存。否则同一代码在默认值变化后可能产生不同结果。

## 三阶段调试比一次跑全样本更可靠

第一阶段只跑几天，用固定小样本打印所有中间变量并手算；第二阶段选择包含调仓、停牌、分红或跳空的短区间，检查订单生命周期；第三阶段才跑完整历史、样本外与压力版本。每阶段通过后再进入下一阶段。

直接运行十年历史会把错误埋进成千上万行数据，漂亮净值反而让人减少怀疑。

## 读报告要沿着因果链

先确认组合真正持有什么、何时交易；再查看毛收益与基准差；随后扣除费用和滑点；最后检查波动、回撤和容量。绩效指标是这条链的结果，不是起点。

把总收益按市场暴露、信号、仓位、费用和现金拖累拆开。若策略收益主要来自长期满仓 Beta，就不能把它全部解释为均线择时能力。

## 订单审计模板

对每笔抽样订单保存：触发信号使用的数据截止时间、目标仓位、提交时间、订单类型和数量、平台撮合条件、成交时间与价格、费用、未成交原因以及成交后的现金和持仓。优先抽查首次交易、方向反转、跳空、涨跌停、停牌恢复和回测最后一日。

订单层若无法解释，净值层就不具备可信度。特别要检查回测结束时未平仓头寸是否被错误忽略或强制按理想价格结算。

## 跨平台对账从第一处差异开始

先对齐交易日与原始价格，再对齐复权和证券状态，之后比较信号、订单、成交、费用、现金和净值。定位第一处差异，并判断它属于数据、策略还是撮合，而不是调整参数让最终收益碰巧接近。

平台差异本身可以成为模型风险报告：若关键结论只在一套默认规则下成立，策略稳健性不足。

## 可复现包应包含什么

至少保存策略说明、源代码提交号、依赖与平台版本、全部参数、输入数据标识、运行日志、逐日净值、订单成交表、指标、压力结果和已知限制。另附一条从零运行的操作说明，使未参与开发的人能够复现。

## 实战交付：让别人能够独立复现

围绕“在聚宽/米筐上完成一次完整回测并看懂报告”形成可交付的研究闭环。完工标准不是代码在作者电脑上运行过一次，而是另一位读者能按说明重建环境、运行测试并解释输出。

1. 冻结需求、输入字段、参数、信号时点、成本口径和输出结构。
2. 把数据校验、策略逻辑、账本、指标、日志和异常处理拆成可测试模块。
3. 使用同一份输入分别运行 Python 与 R，实现逐日结果与指标对账。
4. 保留 README、运行命令、测试记录、已知限制和上线前检查清单。

## 证据、边界与风险

- **参考资料**：
  - [Backtrader 官方文档](https://www.backtrader.com/docu/)：事件驱动回测框架的行为定义。
  - [Python logging 官方文档](https://docs.python.org/3/library/logging.html)：结构化日志与严重级别的实现依据。
- **适用条件与边界**：平台回测结果取决于撮合、费率和数据实现；模拟交易仍不能完整复现实盘排队、冲击和故障。
- **主要失败模式**：研究与生产代码分叉、日志不可追溯、上线无回滚、告警无责任人、收益无法归因。

## 常见误区与修正

- 只交付代码片段而没有输入、环境和运行说明；这不构成可复现产物。
- Python 与 R 使用不同默认参数或缺失值规则；跨语言对账必须逐列进行。
- 把回测通过等同于可实盘；模拟交易、权限隔离、监控和故障恢复仍需独立验收。

## 实战验收清单

- [ ] 从干净环境可按 README 一次运行成功
- [ ] 输入校验和关键逻辑有自动测试
- [ ] Python 与 R 输出在约定容差内一致
- [ ] 日志、监控、异常恢复和风险限制均有文档

## 本讲小结

- 平台默认参数必须显式记录。
- 先审计订单，再相信绩效曲线。
- 回测产出应包含完整可复现材料。
