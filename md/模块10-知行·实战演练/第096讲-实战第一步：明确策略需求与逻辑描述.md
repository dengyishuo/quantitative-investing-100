# 第096讲 实战第一步：明确策略需求与逻辑描述

> 风险提示：本文仅用于量化投资知识教育，不构成任何投资建议。实盘交易部署会产生真实损失，必须经过授权、测试和独立风控。

## 本讲目标

- 把策略需求写成可测试规范。
- 区分经济假设、信号、组合与约束。
- 建立上线验收与失败标准。

## 先写需求，不先写代码

策略项目应从“解决什么问题”开始：追求绝对收益、降低回撤、提供对冲还是跟踪基准。目标不同，数据与评价也不同。

## 一页策略说明书

1. **目标与基准**：要超过谁，风险预算多少。
2. **交易范围**：市场、资产、流动性和排除条件。
3. **假设**：优势为何存在，谁在另一侧。
4. **信号**：输入、公式、频率和时点。
5. **组合**：权重、持仓数、再平衡和约束。
6. **执行**：订单时间、类型、显性交易费用和成交模型。
7. **风控**：单票、组合、回撤与异常。
8. **验收**：样本外、成本、稳健性和容量标准。

## 模糊词清理

把“趋势明显”“估值合理”“风险较低”改成字段、窗口、阈值和比较对象。仍需人工判断的部分也要记录输入与权限。

## 失败定义

在实验前写出什么结果会否定假设、什么偏离会暂停实盘交易。没有失败标准，研究会不断加条件直到曲线变好。

## 最小可行策略

先实现最简单基线，跑通数据—信号—订单—账本—报告，再增加复杂度。工程闭环比首版收益高更重要。

## 从一句想法拆成五层规范

“做一个低回撤的趋势策略”还不是需求。应依次拆成：经济假设说明为什么可能存在优势；信号规范说明何时、用什么数据计算；组合规范说明分数怎样变成权重；执行规范说明何时、以什么订单交易；治理规范说明如何监控、暂停和恢复。

五层要能单独测试。即使回测收益不理想，也能判断失败来自假设、信号、组合、成交还是运营，而不是把所有问题混进一条净值曲线。

## 教学案例：把“趋势明显”改写成规则

模糊版本：“价格趋势明显时买入，趋势变坏时卖出。”可测试版本应进一步写明：目标市场和证券池；使用何种复权收盘价；短长窗口；信号在收盘后形成；下一可交易时点下单；无信号时持有现金；停牌和涨跌停如何处理；费用和滑点口径；最大仓位和暂停条件。

改写后仍不能证明策略有效，但任何实现者都能对同一日期给出同一目标仓位。可复现是评价有效性的前提。

## 需求必须带“非目标”

项目还要明确首版不解决什么。例如只支持日频、不做空、不处理盘中订单、不连接真实账户、不追求最优参数。非目标可以防止研究范围不断扩张，也让验收者知道哪些缺口是有意保留，而非遗漏。

当新需求出现时，应作为新版本评估数据、测试和风险影响，而不是悄悄塞进原规则。

## 验收标准要能判定通过或失败

“夏普较高”“回撤可接受”都无法验收。可写成四类标准：正确性要求账本与手算一致；研究性要求通过时间样本外和成本压力；风险性要求集中度、回撤与压力损失在预算内；工程性要求定时运行、故障告警、重启对账和回滚演练通过。

具体阈值应由策略、市场与组织风险预算决定，并在实验前冻结。未通过时应记录失败，而不是移动门槛直到通过。

## 建立需求到测试的追踪表

每条需求分配唯一编号，并对应数据字段、代码模块、自动测试、监控指标和负责人。例如“信号只能使用当日收盘前可得数据”应对应特征时间契约、无前视测试和生产延迟告警。

追踪表能回答一项规则修改会影响哪些测试和运营环节，也能防止文档写了规则、代码却从未实现。

## 最小可行策略的交付物

首版至少包括一页策略说明书、固定小样本、可运行代码、逐日信号与订单、账户账本、基础报告、自动测试和已知限制。它不追求最高收益，而是证明整条链能被独立复现。后续每增加一个因子或约束，都应说明相对这个基线增加了什么可验证价值。

## 实战交付：让别人能够独立复现

围绕“实战第一步：明确策略需求与逻辑描述”形成可交付的研究闭环。完工标准不是代码在作者电脑上运行过一次，而是另一位读者能按说明重建环境、运行测试并解释输出。

1. 冻结需求、输入字段、参数、信号时点、成本口径和输出结构。
2. 把数据校验、策略逻辑、账本、指标、日志和异常处理拆成可测试模块。
3. 使用同一份输入分别运行 Python 与 R，实现逐日结果与指标对账。
4. 保留 README、运行命令、测试记录、已知限制和上线前检查清单。

## 参考资料

- [Backtrader 官方文档](https://www.backtrader.com/docu/)：事件驱动回测框架的行为定义。
- [Python logging 官方文档](https://docs.python.org/3/library/logging.html)：结构化日志与严重级别的实现依据。
- **适用条件与边界**：平台回测结果取决于撮合、费率和数据实现；模拟交易仍不能完整复现实盘排队、冲击和故障。
- **主要失败模式**：研究与生产代码分叉、日志不可追溯、上线无回滚、告警无责任人、收益无法归因。

## 实战验收清单

- [ ] 从干净环境可按 README 一次运行成功
- [ ] 输入校验和关键逻辑有自动测试
- [ ] Python 与 R 输出在约定容差内一致
- [ ] 日志、监控、异常恢复和风险限制均有文档

## 本讲小结

- 策略需求应覆盖目标、数据、信号、组合、执行、风控与验收。
- 模糊词必须转成可观察条件。
- 先定义失败，再开始实验。
